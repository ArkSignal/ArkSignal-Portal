Everything above stays on the hub's own disk, so losing the disk would lose the backups too. The Off-Site Copy sends encrypted copies somewhere else, on two schedules: a small copy (the portal's database with every flight, history, station and setting, the hub's secret keys and compose files, and Grafana) every day, and a big copy (statistics history and the hub's own traffic history) every week, each as its own file.

Backing up to a NAS: the safe choices

The copies are encrypted with the Encryption Passphrase before they leave the hub, so the NAS only ever holds scrambled files. These are the ways to get them there, safest first. None of them needs port 22 open to the internet.

  1. WebDAV over HTTPS (the usual choice): on the NAS install the WebDAV Server package and allow HTTPS only. Make a user just for this with read/write on one shared folder and nothing else. Reach it through the reverse proxy you already run (a name like https://drive.example.org/ShareName on port 443, with a valid certificate). The proxy must pass the path through unchanged: the NAS serves each shared folder at /ShareName, and a proxy that adds or removes a prefix such as /webdav makes listing and reading fail even though writing works, and in the proxy allow only the hub's public address and set its upload size limit to unlimited (nginx: client_max_body_size 0), because the big copy is one large file. Choose WebDAV above, put the full https address in Web Address (the shared folder it names must already exist; the Folder below it is created for you), then the user and password.
  2. A private VPN between the hub and the NAS (WireGuard): then SFTP or SMB can be used because nothing is open to the internet at all. Use the NAS's VPN address as Host.
  3. S3-compatible storage: the NAS maker's cloud object storage (a real copy in another place, paid for) or MinIO on the NAS behind the HTTPS proxy. Choose S3-compatible bucket and fill in the endpoint, bucket and keys.

Do not use plain FTP, WebDAV on http, or SFTP or SMB through a port opened to the internet. Save, then press Test the Connection: it writes, reads back and deletes a small file. When it works, tick Make off-site copies and save.

For a share, start with the share name: backups/adsb. The copies are written inside this folder, in small and big sub-folders.

Getting a Copy Back

The database part can be restored from this page like any backup once you have decrypted the small copy. To list, decrypt and unpack copies from the destination, run on the hub: docker run --rm -it -v /opt/adsb:/opt/adsb mallison01/adsb-backup:stable restore. It asks for the destination details and your passphrase; nothing else on the hub is touched until you copy files back yourself.
