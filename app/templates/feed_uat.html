Feed UAT (978 MHz)

The second ADS-B datalink, used only in the United States. It needs its own radio and antenna, but nothing extra is sent to the network: the 978 MHz aircraft travel through the same feed as your ADS-B.
{% call sec('the-short-version', 'The Short Version', True) %}

With a second radio (serial number 00000978) and a 978 MHz antenna, run the dump978 container next to your ultrafeeder and add this line to the ULTRAFEEDER_CONFIG (the line before it needs a semicolon):

adsb,dump978,30978,uat_in

There is no separate feed line for us: your 978 MHz aircraft go out through the line from the ADS-B page. Without a 978 MHz radio you lose nothing, because the network still shows UAT aircraft heard by the stations that have one.

{% endcall %} {% call sec('how-it-works', 'How It Works', True) %}

UAT (Universal Access Transceiver) is the second ADS-B datalink, used only in the United States. Light general-aviation aircraft flying below 18,000 ft (18,000 ft is where airliners and most jets, which use 1090 MHz, take over) can choose either; many choose UAT because it also lets them receive weather and traffic information in the cockpit. In Arkansas that means many of the small planes you would otherwise never see.

It is a different frequency, so your 1090 MHz receiver cannot hear it. A second radio tuned to 978 MHz feeds the dump978 container, which decodes it and hands the result to your ultrafeeder. From there the aircraft are merged into your normal feed and appear on the map as UAT/ADS-R.

ADS-R is the same data rebroadcast by ground stations onto 1090 MHz; the map groups both as UAT / ADS-R. See the source table on the ADS-B page.

{% endcall %} {% call sec('what-you-need', 'What You Need', True) %}
  • A working ADS-B feed with an ultrafeeder (or a decoder that can take a 978 MHz input).
  • A second USB radio (RTL-SDR dongles work), with its serial number set to 00000978 so the two radios can tell each other apart.
  • A 978 MHz antenna. A 1090 MHz antenna is the wrong length.
  • The dump978 container (a second service in your compose.yaml), on the same computer.
  • Your latitude and longitude for the dump978 container (the same as the ADS-B ones).

ItemOptions and Notes

ComputerThe same Raspberry Pi 3, 4 or 5 or small Linux machine as for ADS-B; UAT adds little load.
{% endcall %} {% call sec('hardware-setup', 'Hardware Setup', True) %}
  1. Set the serial number of the 978 MHz radio before plugging in both radios, so they cannot be mixed up: with only that radio connected, run rtl_eeprom -d 0 -s 00000978, unplug it and plug it back in. rtl_test lists the serial numbers.
  2. If your 1090 radio has its own serial number set, tell the ultrafeeder with READSB_RTLSDR_DEVICE=SERIAL.
  3. Mount the 978 MHz antenna outdoors, high, with a clear view, about a metre or more from the 1090 antenna.
  4. Connect it to the 978 radio with a short run of good coax, with the filter or LNA (if any) close to the antenna.
  5. Plug both radios into separate USB ports and give the computer a reliable network connection.
{% endcall %} {% call sec('software-setup', 'Software Setup', True) %}

Add the dump978 service to the compose.yaml from the ADS-B software setup, and the line that reads it to the ultrafeeder:

services:
  ultrafeeder:
    environment:
      # ...everything from the ADS-B page, then in ULTRAFEEDER_CONFIG add the 978 line:
      - ULTRAFEEDER_CONFIG=
        adsb,{{ feed_host }},{{ feed_port }},beast_reduce_plus_out;
{% if mlat_enabled %}        mlat,{{ feed_host }},{{ mlat_port }};
{% endif %}        adsb,dump978,30978,uat_in

  dump978:
    image: ghcr.io/sdr-enthusiasts/docker-dump978
    container_name: dump978
    restart: unless-stopped
    device_cgroup_rules:
      - "c 189:* rwm"
    environment:
      - TZ=America/Chicago
      - DUMP978_RTLSDR_DEVICE=00000978
      - DUMP978_SDR_GAIN=autogain
      - LAT=YOUR_LATITUDE
      - LON=YOUR_LONGITUDE
    volumes:
      - /opt/adsb/dump978/globe_history:/var/globe_history
      - /dev/bus/usb:/dev/bus/usb

Each line in ULTRAFEEDER_CONFIG except the last needs a semicolon. Recreate with docker compose up -d; docker logs dump978 should show messages after a few minutes.

Not using ultrafeeder?

With readsb, add the decoder as an input: --net-connector dump978,30978,uat_in. PiAware users run dump978-fa and its skyaware978 output and need a way to merge it into the feed; ultrafeeder is the easier route.

{% endcall %} {{ after('uat') }} {% call sec('check', 'How to Tell It Works', True) %}

The site can tell which stations send UAT: every message a 978 MHz radio decodes is marked as UAT on its way through your ultrafeeder, and the hub knows which station sent it. So there is nothing to switch on, and nothing for you to report.

  • Your station page (My Account > My Stations > My Feeders, then your station) has a UAT (978 MHz) section that says receiving with the time of the last message and the number of UAT aircraft in the last hour.
  • Am I Feeding shows the same line next to your station.
  • The public station list and each station's page show a UAT tag while a station is sending UAT, and the public data (/api/feeders.json) has a uat flag.

A station that has sent no UAT shows none yet. That is not proof of a fault: UAT is used only by some aircraft, mostly below 18,000 feet, so a quiet stretch with no UAT aircraft in range looks the same as a radio that is not connected. Watch for a few hours around busy flying times, and check docker logs dump978 if it never shows.
