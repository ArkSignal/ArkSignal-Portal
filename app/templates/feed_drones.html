How to Feed Drone Remote ID

Share the drones your Remote ID receiver hears with {{ site_name }}. They appear on Drones, on its map and as a layer on the other maps. A receiver is a few dollars of hardware, and a drone near you is heard from a few hundred meters away.
{% call sec('the-short-version', 'The Short Version', True) %}

Run the ArkSignal bridge next to your receiver:

cat /dev/ttyUSB0 | python3 rid_bridge.py {{ base }}/drones/push/YOUR-KEY

The bridge is one small file you download from {{ bridge }}. Your key is the end of the private upload address on your station's card: My Account > My Remote ID Stations. It reads what your receiver prints (one message per line) and sends it on.

First create an account and add the station: that gives you the upload address. Remote ID is a public broadcast that regulators require; the site still keeps pilots' privacy (see below).

{% endcall %} {% call sec('how-it-works', 'How It Works', True) %}

Remote ID is the digital license plate of a drone. Since 2023 the FAA has required most drones sold or flown in the United States to broadcast who they are (a serial number or registration), what they are, and where they are, how high and how fast, a few times a second, over Wi-Fi or Bluetooth. Anyone nearby can read it with a cheap receiver.

Your receiver turns what it hears into lines of text. The bridge collects them and sends them over https to an address on this site that only you know. The site decodes them, keeps each drone's newest position and details and a short trail, and shows them to everyone.

Radio linkWhat it is
Wi-Fi (NAN and beacon)2.4 GHz Wi-Fi frames. Most newer drones; heard by an ESP32 or a laptop Wi-Fi card.
Bluetooth 4 and 5Legacy advertising and long-range (coded PHY). DJI and many others; heard by an ESP32-S3 or a Bluetooth 5 adapter.

The site keeps drones heard in the area it covers ({{ area }}: south, west, north, east) and ignores the rest.

{% endcall %} {% call sec('what-you-need', 'What You Need', True) %}
  • A receiver: an ESP32-S3 board (a few dollars) running a Remote ID scanner firmware such as the OpenDroneID receiver or DroneScout, or an Android phone running the OpenDroneID app. A Bluetooth 5 and Wi-Fi capable board hears the most.
  • A power supply and a place with a clear view of the sky around: a window or a mast, as high as you can. Range is a few hundred meters to a few kilometers depending on the drone and the surroundings.
  • A small always-on computer (a Raspberry Pi or any Linux or Windows machine) that the receiver plugs into, with Python 3 for the bridge.
  • A network connection that can reach {{ base | replace('https://', '') }} over https.

{% endcall %} {% call sec('hardware-setup', 'Hardware Setup', True) %}
  1. Flash the scanner firmware on the board, following the firmware's own instructions.
  2. Plug the board into the computer by USB. On Linux it appears as /dev/ttyUSB0 or /dev/ttyACM0; on Windows as a COM port.
  3. Look at what it prints (cat /dev/ttyUSB0) while a drone is flying nearby. Lines of hex digits, or JSON with an id and a position, are what the bridge sends on.
{% endcall %} {% call sec('software-setup', 'Software Setup', True) %}

1. Add a station and get its upload address

Open My Account > My Remote ID Stations, choose Add a Station and name it. Its card shows the private Upload Address.

2. Download and run the bridge

curl -O {{ bridge }}
cat /dev/ttyUSB0 | python3 rid_bridge.py {{ base }}/drones/push/YOUR-KEY

If your receiver sends its messages over the network instead, give the bridge a UDP port to listen on: python3 rid_bridge.py {{ base }}/drones/push/YOUR-KEY --udp 5556. It prints a line each time it sends a batch.

3. What the site understands

Each line is the raw hex of a Remote ID message or message pack (the site decodes it itself), or a JSON object of what your receiver already decoded, with any of: id, id_type, ua_type, lat, lon, alt (meters), height, speed (meters per second), heading, vspeed, status (1 on the ground, 2 in the air), op_id and desc. Add src (the transmitter's address) when messages arrive one at a time, so a position is joined to the drone's ID.

4. Keep it running

On Linux a systemd service starts the bridge at boot. Save this as /etc/systemd/system/arksignal-rid.service and run sudo systemctl enable --now arksignal-rid:

[Unit]
Description=ArkSignal Remote ID bridge
After=network-online.target

[Service]
User=pi
ExecStart=/bin/sh -c 'cat /dev/ttyUSB0 | /usr/bin/python3 /home/pi/rid_bridge.py {{ base }}/drones/push/YOUR-KEY'
Restart=always

[Install]
WantedBy=multi-user.target

5. Test it

Without a receiver you can still check the address works: curl -d '{"id":"TESTDRONE0001","lat":35.08,"lon":-92.44,"alt":120,"speed":9,"heading":90,"status":2}' {{ base }}/drones/push/YOUR-KEY answers {"ok": true ...} and the test drone shows on Drones. Am I Feeding? shows each of your stations and when it last reported.

{% endcall %} {% call sec('your-data-and-privacy', 'Your Data and Privacy', False) %}
  • Remote ID is broadcast openly by regulation. The site shows only the drone's own position and details.
  • The operator's location, which some drones also broadcast, is {% if operator %}stored and shown on the drone's page because an administrator turned that on{% else %}not stored or shown (an administrator can turn that on in Settings){% endif %}: it can point at a person's home.
  • A pilot can ask for a drone ID to be hidden (Contact).
  • Your station has no map position on the site: only its name and the place you typed, and only if you leave the name on. The upload address is a secret: if it leaks, make a new one on your station's card.
