{% endcall %} {% call sec('connect', 'How to Connect a Gateway', True) %}

This community has its own topic on the broker: {{ connect.root }}. Its logins can write there and nowhere else, so what your gateways send is kept apart from everyone else's, and a node heard there counts as this community's. In the Meshtastic app open Settings, Radio Configuration, Module Configuration, MQTT on the gateway node and set:

MQTT enabledOn
Address{{ connect.host }}{% if connect.port %}:{{ connect.port }}{% endif %}
Username and passwordOne of the logins above (the password is shown once when it is made)
TLS enabled{{ 'On (this port uses TLS)' if connect.tls else 'Off for a plain port; On when the port is 8883' }}
Root topic{{ connect.root }}
Map reportingOn if the node should appear on the maps (it sends its name, role and a position at the precision its owner chooses)
Proxy to clientOn only when the node has no Wi-Fi of its own and uses the phone's connection

On the channel you want shared (Settings, Channels, the channel, Uplink enabled) turn Uplink on. Turn Downlink on only for a channel that must be carried to a remote place, and only on a node that has a downlink login: it then sends out over the radio what other gateways of this community uplinked, so use it with a low hop limit and never on a channel two of your gateways already reach each other on.

  • Uplink only logins write to this community's topic and are sent nothing back.
  • Uplink and downlink logins also read this community's topic, and only that one.
  • The firmware does not send a packet it got from the broker back to the broker, which is what keeps two gateways from looping; the site's own loop guards and rate rules are set by the administrators.
  • Encrypted packets are never read or kept by this site, whatever the node sends.
