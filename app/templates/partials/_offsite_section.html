Everything above stays on the hub's own disk, so losing the disk would lose the backups too. The Off-Site Copy sends encrypted copies somewhere else, on two schedules: a small copy (the portal's database with every flight, history, station and setting, the hub's secret keys and compose files, and Grafana) every day, and a big copy (statistics history and the hub's own traffic history) every week, each as its own file.

Setting up a NAS (a network storage box) as the off-site copy. The menu names differ between makes; the steps are the same.

  1. On the NAS, switch on its SFTP service (some call it SSH file transfer; leave the port at 22 or choose another one). Do not switch on plain FTP.
  2. Make a user just for this, for example arksignal-backup, with a long password. Give it read/write on one shared folder (for example backups) and no access to any other folder, and allow it to use SFTP only.
  3. Make the NAS reachable from this hub: put its address in Host below (a dynamic DNS name, or a VPN address if the hub and the NAS share a VPN). Over the internet, forward one router port to the NAS, let the NAS firewall accept that port only from the hub's public address, and switch on its automatic blocking of repeated failures. A VPN is safer than an open port.
  4. Below, enter the host, the port (if not 22), the user and password, and as Folder the shared folder and a sub-folder, for example backups/arksignal. Choose a long Encryption Passphrase and keep a copy of it away from the hub: the files on the NAS are encrypted and cannot be read without it.
  5. Save, then press Test the Connection. It writes, reads back and deletes a small file. When it works, tick Make off-site copies and save.

You can use an SSH key instead of the password (add its public key to the user's authorized_keys on the NAS; some NAS boxes need the user's home folder switched on for that). The NAS needs no backup software of its own: the copies are ordinary files in the folder you chose.

For a share, start with the share name: backups/adsb. The copies are written inside this folder, in small and big sub-folders.

Getting a Copy Back

The database part can be restored from this page like any backup once you have decrypted the small copy. To list, decrypt and unpack copies from the destination, run on the hub: docker run --rm -it -v /opt/adsb:/opt/adsb mallison01/adsb-backup:stable restore. It asks for the destination details and your passphrase; nothing else on the hub is touched until you copy files back yourself.
