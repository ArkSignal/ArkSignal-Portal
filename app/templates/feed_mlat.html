Feed MLAT

Multilateration finds aircraft that do not broadcast a position. It uses the same receiver and the same container as your ADS-B feed, so most stations send both. This page has the settings, what the position has to be, and how to check it.
{% call sec('the-short-version', 'The Short Version', True) %}

Your ADS-B feed from the ADS-B page must already work. Then add this line to the same ULTRAFEEDER_CONFIG (the line before it needs a semicolon at the end) and set the three settings below it:

mlat,{{ feed_host }},{{ mlat_port }}
  • MLAT_USER: your Station ID (letters, digits, dashes and underscores). If you already use another name, keep it and enter it as the MLAT User Name on your station page.
  • READSB_LAT, READSB_LON and READSB_ALT: your antenna's true position, within a few metres, with the altitude above sea level.
  • UUID: the same one you use for the ADS-B feed.

Your exact position is held only by the MLAT server and is never shown publicly. Recreate the container, then check Am I Feeding?: it shows MLAT status in plain words.

{% endcall %} {% call sec('how-it-works', 'How It Works', True) %}

MLAT (multilateration) finds aircraft that do not broadcast a position. Radio travels at a fixed speed, so when an aircraft transmits, stations at different distances hear it at slightly different instants, a difference of millionths of a second. If three or more stations record exactly when they heard the same message, the differences place the aircraft at one point in the sky (four stations also give altitude). The same trick, run the other way, is how GPS works.

What your station does: your receiver time-stamps every message it hears with its own clock, and sends those timestamps (not your location data) to the network's MLAT server. The server compares all stations' clocks, using aircraft that do broadcast their position as reference beacons, and calculates positions for the others. The results come back to you and appear on the map labelled MLAT.

Trade-offs: MLAT positions are less exact than ADS-B and arrive a moment later, and only aircraft heard by enough stations get one. It is an extra, not a replacement for your ADS-B feed, which it depends on. See the MLAT network page for who is connected and how well.

{% endcall %} {% call sec('what-you-need', 'What You Need', True) %}
  • A working ADS-B feed. MLAT uses the same receiver, antenna, computer and container; there is nothing extra to buy.
  • An exact position. Your latitude, longitude and the antenna's altitude above sea level must be right to within a few metres, because the whole calculation assumes it. A wrong location does not just fail; it makes your station's timing look bad to the others, and the server will pause it.
  • Neighbours. At least three stations must hear the same aircraft, so MLAT is best where stations overlap. Your station may sit at "connected, waiting for peers" until the next station near you joins; that is normal.
  • A steady receiver: a computer that is not overloaded, a USB radio that is not dropping samples, a correct clock, and a wired network without long delays or gaps.
  • The same UUID in your MLAT line as in your feed, and MLAT_USER set, so the portal can match your MLAT connection to your station and show you its health.

{% endcall %} {% call sec('hardware-setup', 'Hardware Setup', True) %}
  1. Mount the antenna where it will stay, as in the ADS-B hardware setup. Do not move it later without changing the position.
  2. Measure the antenna's latitude and longitude to five decimal places (about a metre) and write them down.
  3. Work out its altitude above sea level: the ground height at that spot plus the height of the antenna above the ground. Use metres or add the unit (320ft).
  4. Use a wired network connection and a power supply that can run the computer and the radio without dips.
{% endcall %} {% call sec('software-setup', 'Software Setup', True) %}

In the same compose.yaml as your ADS-B feed (see the ADS-B software setup), these are the MLAT parts:

    environment:
      - READSB_LAT=YOUR_LATITUDE
      - READSB_LON=YOUR_LONGITUDE
      - READSB_ALT=YOUR_ANTENNA_ALTITUDE_ABOVE_SEA_LEVEL_IN_METERS_m
      - UUID=YOUR_UUID
      - MLAT_USER=YOUR_STATION_ID
      - ULTRAFEEDER_CONFIG=
        adsb,{{ feed_host }},{{ feed_port }},beast_reduce_plus_out;
        mlat,{{ feed_host }},{{ mlat_port }}

Each line except the last ends with a semicolon. Ultrafeeder already contains the MLAT client and starts it from the mlat,... line, so there is nothing extra to install. Recreate the container with docker compose up -d and watch it with docker logs ultrafeeder | grep -i mlat.

Already doing MLAT for other networks

That is fine: the MLAT client runs once per network, so add our mlat,... line next to the others. The position settings are shared by all of them.

Not using ultrafeeder? (readsb, dump1090-fa, PiAware)

Install the separate mlat-client program and run it against your receiver's Beast output:

mlat-client --input-type dump1090 --input-connect 127.0.0.1:30005 \
  --server {{ feed_host }}:{{ mlat_port }} --user YOUR_STATION_ID --uuid YOUR_UUID \
  --lat YOUR_LATITUDE --lon YOUR_LONGITUDE --alt YOUR_ANTENNA_ALTITUDE_IN_METERS \
  --results beast,connect,127.0.0.1:30104
